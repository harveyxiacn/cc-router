# CC Router desktop implementation plan

**Goal:** The owner chose to design and implement a cross-platform GUI in this delivery, retaining the CLI and explicit manual switching.

**Architecture:** Wails 2 stable + React/TypeScript; desktop Go module calls the existing Go packages directly. No HTTP service or credential-reading UI. Official Claude runs in the user's system terminal. Platform-specific terminal adapters are a small boundary, rather than three separate applications.

**Tech stack:** Wails v2, React, TypeScript, Vite. CLI remains a standalone standard-library Go module. Desktop dependencies live in a nested module.

## Why this architecture

CLI-only is convenient for scripts and SSH but not for comparing several accounts and handoffs. Three native GUIs duplicate logic and accessibility/testing effort. Tauri 2 can embed the Go CLI as a sidecar, as contemplated in the original plan, but adds Rust/Go IPC and per-architecture sidecar packaging. Wails reuses the Go services directly. Linux still requires GTK/WebKitGTK; macOS/Windows need native release verification. See https://wails.io/docs/gettingstarted/installation/ and https://v2.tauri.app/develop/sidecar/.

## Interface

- Accounts: name and label, default account, official identity only after an explicit status check, recent 5h/7d reports and observed time, unknown/stale states, add/rename/remove/login/start actions.
- Projects: folder picker, current binding, set/unset binding, launch in selected directory.
- Handoff: generate template, edit/save locally with change-conflict detection, explicit reviewed confirmation, launch selected account in a new conversation.
- Diagnostics: installed Claude version, only source/key names for conflicts, refresh action, no credential fields.
- Usage setup: install the documented local statusline command in the selected profile settings, preserving unrelated fields and refusing to overwrite an existing statusline silently. Custom preparation/switch thresholds. Persist only allowlisted usage numbers/reset/receipt timestamps, never raw statusline payload or transcripts.

Visual direction: compact desktop workspace, ivory surfaces, deep ink navigation, restrained green actions, explicit amber warning states; no synthetic quota data, no fake live status.

## Work packages

1. Root: extend statusline with bounded, atomic, per-account usage snapshots; tests for unknown/stale/corrupt values and no raw payload persistence.
2. Root: internal/desktop service using state/claude/cli; account/project actions, safe handoff read/save, usage setup, terminal adapter. Write failure tests first for metadata actions, overwrite/lock protection and shell quoting boundaries.
3. GPT-6.1-Sol high: desktop Wails wrapper + React UI + frontend tests; call only typed service methods. No runtime mock data. Work only in desktop/ and coordinate API with root.
4. Root + worker reciprocal review: service security and UI behavior. Build Windows desktop, browser-based frontend checks, desktop CI for Linux/macOS/Windows. Record which native behaviors remain unverified.
5. Publish useful CLI and desktop source in the authorized public repository, with tested artifacts and explicit alpha limits.

## Terminal and privacy boundaries

Only validated account names and selected local directory paths reach launch adapters. Official Claude is still started by the tested CLI using argv, never via a constructed shell command. Windows uses the native executable launch API; Linux launches an available terminal with argv; macOS may require a minimal quoted `.command` bridge, which must be isolated, tested and documented. No forced process kill to switch accounts. Existing managed session locks prevent unsafe overlap; external processes remain outside this guarantee.

Reported quota is a last-received observation, not proof the upstream value was freshly queried. Expired windows and old observations display unknown/stale. GUI refresh reads local snapshots and does not poll private quota endpoints.
