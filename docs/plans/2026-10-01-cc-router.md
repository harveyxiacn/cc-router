# CC Router implementation plan

**Goal:** Implement the supplied CC_Router_Project_Plan.docx as an open-source, local Claude Code profile launcher and project handoff CLI.

**Architecture:** A Go executable launches the official Claude Code binary with a stable, private per-account CLAUDE_CONFIG_DIR and inherited terminal streams. Tool-owned metadata is separate from official credentials. No HTTP gateway, token handling, automatic account rotation or request replay.

**Tech stack:** Go standard library; OS primitives where needed; GitHub Actions. Windows native development; Linux/macOS CI and cross-compilation; real authentication/terminal tests remain explicit release gates.

## Design basis and choices

The user's existing plan is the design baseline. Keep explicit selection > project binding > global default > interactive selection; rename labels without moving directories; removal preserves official data. Keep CLI command `ccr` as specified, but document its collision with musistudio/claude-code-router and provide `cc-router` as an alternative binary name.

Options considered: fork a general LLM gateway (substantial out-of-scope protocol and credential machinery); fork a Node profile launcher (closer but different runtime and persistence assumptions); build a small independent Go launcher (selected). Research findings and primary sources are recorded separately.

First delivery is an alpha implementing core commands and automated acceptance tests. It is not a claim of completed 1.0 platform/authentication acceptance. No inferred identity/quota. Future unsupported official status output yields unknown.

## Task 1 — Persistent account and project state

Files: internal/state/state.go, state_test.go, platform-specific file locking/atomic replacement helpers.

1. Write failing tests for stable random IDs, label rename, duplicate names, remove preserving profile data, binding/default precedence, strict import/export without paths/secrets, corruption, and concurrent updates.
2. Run package tests and record the expected missing-behavior failure.
3. Implement versioned accounts.json metadata and bindings, private directories, exclusive cross-process locking, atomic file replacement, strict bounded JSON. No credential reads.
4. Run tests; review both requirement coverage and implementation safety.

## Task 2 — Official CLI adapter and launch guard

Files: internal/claude/{guard,process,status}.go and tests, OS-specific process helpers.

1. Verify current official CLI help and official authentication/settings documentation without logging into accounts.
2. Write failing tests for argv boundaries, current directory, selected profile env, exit status, terminal inheritance, conflict detection and redaction, invalid official status data.
3. Implement direct exec (no shell), environment/config diagnostics, subscription guard, supported status adapter, platform process lifecycle. Never load .credentials.json. Preserve errors for unreadable managed configuration.
4. Use a fixture child process to verify behavior without requests or login. Unsupported settings/managed sources must be disclosed or fail closed rather than described as verified.

## Task 3 — User commands and handoff

Files: cmd/ccr/main.go, internal/cli/{app,handoff}.go and tests.

1. Write failing command tests for init, account add/list/rename/remove, use, bind/unbind, run/login/status/doctor, export/import and handoff/switch.
2. Implement commands with clear errors, pre-launch selection only, explicit delimiter for Claude args; configuration-changing arguments must pass the guard.
3. Generate a user-editable handoff template from Git metadata only, excluding sensitive filenames and raw diffs; never overwrite existing handoff; add local Git exclusion. Switching creates a new session and requires deliberate handoff acknowledgment.
4. Validate command integration against fixture CLI and local temporary Git repositories.

## Task 4 — Review, documentation, publication

Files: README.md, LICENSE, SECURITY.md, docs/research.md, docs/compatibility.md, .github/workflows/ci.yml, scripts/build.ps1.

1. Record source/license/maintenance review; document alpha limits, risk controls, commands, installation and uninstall preservation behavior.
2. Run gofmt, go test ./..., go vet ./..., source vulnerability scan and cross-build target binaries with checksums; CI runs tests on Windows, Linux and macOS and Linux race tests.
3. Perform independent specification and code review; fix findings with regression tests.
4. Inspect staged content for secrets and exclude original private Word document and local toolchain. Commit useful work, create public harveyxiacn/cc-router (already authorized by user), push and inspect CI.

## Acceptance requiring the owner / additional devices

- Two actual subscriptions per platform; official /status identity and billing confirmation.
- macOS Keychain, signing and notarization; CachyOS real terminal verification.
- Real terminal Ctrl+C, resize and descendant cleanup on supported shells.
- Current CLI future compatibility, enterprise registry/MDM/cloud policy behavior.

These cannot be replaced by mocks or cross-compilation and will be reported as unverified until exercised.
